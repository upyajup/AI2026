01. 개요 & 배경 (Overview)

왜 어린이보호구역 안전 네비게이션인가?

기존 내비게이션의 한계 (Problem)

기존의 지도 및 길안내 앱은 "최단 거리" 또는 "최단 시간"만을 핵심 목표로 설정합니다.

이로 인해 CCTV가 없는 어두운 골목길, 좁아서 보차 분리가 되지 않는 위험 도로, 차량 통행량이 많은 구간을 어린이 보행자에게 안내하는 문제가 발생합니다.

Safe Zone Navigator의 솔루션 (Solution)

보호구역 내 CCTV 설치 대수, 도로 너비(m), 주변 보호구역 밀집도 데이터를 수집 및 수치화합니다.

보행 위험도를 비용(Cost) 패널티로 변환하는 Modified A* 알고리즘을 통해, 어린이가 안심하고 다닐 수 있는 최우선 안전 경로를 정밀 제공합니다.

02. 핵심 기능 요구사항 (Functional Requirements)

PRD 핵심 기능 명세서

FR-01

마커 시각화 & 클러스터링

전국 16,000개 이상의 위치를 안전점수에 따라 색상(녹/황/적)으로 구분하고, 대용량 처리 시 MarkerCluster를 통해 가독성을 확보합니다.

Leaflet.js + OSM 필수 구현
FR-02

마커 상세 팝업 명세

구역 클릭 시 대상시설명, 도로명주소, 도로폭(m), 관할 경찰서, CCTV 설치 대수, 최종 종합 안전점수를 상세 출력합니다.

Interactive Popup 필수 구현
FR-03

안전점수 & 히트맵 시각화

CCTV(40%) + 도로폭(35%) + 밀집도(25%) 가중치를 합성하여 0~100점 스코어를 계산하고 히트맵 오버레이 레이어로 밀도를 표시합니다.

Leaflet.heat 우선순위 높음
FR-04

안전 경로 탐색 (A* Engine)

출발지-목적지 간 보호구역을 그래프 노드로 산출하고, (100-안전점수) 패널티 비용을 반영하여 안전 보행 경로를 탐색합니다.

Modified A* Algo 우선순위 높음

03. 안전점수 산출 알고리즘 (FR-03 Calculator)

실시간 안전점수 계산기 시뮬레이터

점수 산출 가중치 공식

Score = (CCTV × 0.40) + (RoadWidth × 0.35) + (Density × 0.25)
  • CCTV 점수 (최대 40점):
    설치 대수 10대 이상 시 만점 (40점). 비례 정규화 적용.
  • 도로폭 점수 (최대 35점):
    도로 너비 6m 이상 시 만점 (35점). 결측 시 전국 평균(8m) 대입.
  • 밀집도 점수 (최대 25점):
    반경 500m 내 타 보호구역 중복 수 — 많을수록 사각지대/혼잡 위험 증가로 감점 역산.

04. 안전 경로 탐색 알고리즘 (FR-04 Mechanism)

Modified A* 알고리즘 & 옵션 비교

기본 거리 비용 (Distance)
Edge Distance (km)

두 좌표 간 하버사인(Haversine) 실거리

위험 패널티 (Safety Penalty)
(100 - Score) × α

낮은 안전점수일수록 이동 비용을 대폭 증가시킴

최종 A* 엣지 가중치 (Cost)
Distance + Penalty

패널티가 반영된 최적 탐색 노드 선택

경로 탐색 구현 방식 검토 (Open Issue Option Comparison)

Option A 외부 OSRM API 연동
실제 도로망 기반 보행 경로 + 보호구역 웨이포인트
  • 실제 도보 인도(Pedestrian Road) 지도와 정확히 일치
  • 외부 API 호출 의존성 및 네트워크 레이턴시 존재
  • 보호구역 지점 우회 가중치 적용 시 API 커스텀 파라미터 필요
Option B (추천 채택안) 클라이언트 자체 그래프 Engine
보호구역 포인트 기반 독립 그래프 A* 탐색
  • 외부 서버 및 API 키 없이 브라우저 단독으로 100% 작동
  • CCTV/도로폭 데이터 반영 패널티 연산이 실시간으로 신속함
  • 네트워크 연결 불량 환경에서도 안정적 구동 보장
